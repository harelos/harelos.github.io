Product overview

See the campaign.

Foundry gives one ecommerce job a brief, a small team, and a file you can inspect against named criteria. The first Windows pilot focuses on one product and one current offer.

The first job

From approved inputs to a pack for review.

The operator supplies the product, offer, audience, source material, and criteria. The maker drafts distinct concepts. A reviewer checks the offer and evidence. The operator reads the generated file, requests a revision, or accepts that exact version.

One briefCurrent facts and a named output.
Two rolesOne prepares; one challenges the work.
One decisionInspect the file and check every acceptance item.

What you receive

A pack with parts you can inspect.

The pilot acceptance target is a complete planning file. You judge strategy, copy quality, and every customer-facing promise before you mark the file accepted.

01 / SOURCE

Evidence brief

Product, offer, buyer, sources, and missing facts.

02 / ANGLES

Three concepts

Different reasons to buy, with two text drafts and three headlines per concept.

03 / PAGE

One aligned outline

The opening promise, proof, and decision path for the selected concept.

04 / DECIDE

Your review

Read the actual file and check every criterion. Foundry records the version you accept.

Where work happens

Browser planning. Local execution.

The phone-friendly web planner writes a mission file in the browser. The Windows desktop pilot uses an eligible Claude Code or Codex sign-in and a folder you choose. The web page cannot read that folder or run your local agents.
